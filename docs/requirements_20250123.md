# 異步雙軌推理架構需求文檔

**日期**: 2025-01-23  
**需求類型**: 架構設計與數據庫遷移

## 需求概述

實現一個**雙軌異步推理架構（Dual-Track Async Reasoning Architecture）**，並將數據存儲從 JSON 文件遷移到 PostgreSQL 數據庫。

## 核心需求

### 1. 異步雙軌架構

#### 1.1 架構名稱
- **雙軌異步推理架構（Dual-Track Async Reasoning Architecture）**
- 也稱為：主從異步處理架構、快速響應 + 深度推理架構

#### 1.2 架構設計
- **快速響應軌道**：
  - 使用小模型（如 Gemini Flash）負責即時響應用戶
  - 快速提取和收集用戶數據
  - 從問題佇列中提取問題並快速提問

- **深度推理軌道**：
  - 使用大模型（如 Llama 3.3 70B）在背景異步執行
  - 分析數據完整性和邏輯性
  - 生成問題並寫入問題佇列
  - 不阻塞用戶響應流程

#### 1.3 工作流程
1. 用戶發送消息
2. 小模型快速提取數據並響應
3. 異步觸發大模型進行深度推理
4. 大模型生成問題並寫入佇列
5. 下次用戶交互時，小模型從佇列提取問題快速提問

### 2. 問題佇列機制

#### 2.1 問題優先級
- **基本信息**（name, phone, email）：優先級 1-3
- **教育背景**（school, major, degree）：優先級 4-6
- **工作經歷**：優先級 7-10
- **技能與證書**：優先級 11+

#### 2.2 問題管理
- 問題去重與合併
- 優先級排序
- 已回答問題標記
- 自動移除已獲取數據的問題

### 3. PostgreSQL 數據庫遷移

#### 3.1 Docker 設置
- 在最外層創建 `docker-compose.yml`
- 配置 PostgreSQL 15+ 容器
- 設置環境變量（用戶名、密碼、數據庫名）
- 端口映射（5432）
- 數據持久化（volume）

#### 3.2 數據庫初始化
- 創建 `scripts/` 目錄
- 包含初始化 SQL 腳本（`init.sql`）
- 創建必要的數據庫表結構：
  - `sessions` 表：存儲會話數據
  - `question_queue` 表：存儲問題佇列（或使用 JSONB）
  - 索引優化

#### 3.3 數據庫管理腳本
- `init_db.sh` - 初始化數據庫
- `migrate_from_json.py` - 從 JSON 遷移數據到 PostgreSQL
- `backup_db.sh` - 數據庫備份
- `reset_db.sh` - 重置數據庫（開發用）

#### 3.4 SessionManager 重構
- 移除 JSON 文件讀寫邏輯
- 使用 asyncpg 或 SQLAlchemy 進行異步數據庫操作
- 實現連接池管理
- 支持事務處理

### 4. Makefile 更新

新增以下命令：
- `make db-up` - 啟動 PostgreSQL 容器
- `make db-down` - 停止 PostgreSQL 容器
- `make db-init` - 初始化數據庫表結構
- `make db-migrate` - 執行數據遷移
- `make db-reset` - 重置數據庫（開發用）
- `make db-logs` - 查看數據庫日誌

### 5. 依賴更新

- 更新 `pyproject.toml`，添加 PostgreSQL 驅動依賴
  - `asyncpg`（推薦，異步支持）
  - 或 `psycopg2-binary`（同步版本）

## 適用場景分析

### 在索要建立信息時的優勢

1. **快速響應**：小模型可以立即響應用戶，收集基本信息
2. **智能分析**：大模型在背景分析數據完整性，生成精準的追問策略
3. **問題佇列**：確保不遺漏關鍵信息，按優先級有序提問
4. **用戶體驗**：用戶無需等待大模型推理，體驗流暢

### 落地方式

1. **階段一**：實現問題佇列機制和背景推理服務
2. **階段二**：整合到現有 Orchestrator 流程中
3. **階段三**：遷移數據存儲到 PostgreSQL
4. **階段四**：優化和性能調優

## 技術細節補充

### 異步觸發時機
- **立即觸發**：數據發生變化時
- **延遲觸發**：用戶完成一輪對話後 0.5 秒（避免阻塞）
- **手動觸發**：用戶明確要求「檢查」或「分析」時

### 問題去重邏輯
- 相同字段的問題只保留優先級最高的
- 相似語義的問題合併為一個
- 已獲取數據的問題自動移除

### 數據庫連接配置
- `DATABASE_URL` - PostgreSQL 連接字符串
- `DB_POOL_SIZE` - 連接池大小
- `DB_MAX_OVERFLOW` - 最大溢出連接數

## 預期效果

1. **響應速度提升**：小模型快速響應，用戶體驗流暢
2. **提問質量提升**：大模型深度分析，問題更精準
3. **資源優化**：大模型異步執行，不阻塞主流程
4. **數據收集效率**：問題佇列機制確保不遺漏關鍵信息
5. **數據持久化**：PostgreSQL 提供可靠的數據存儲和查詢能力
