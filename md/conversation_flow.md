# 聊天生成简历 Agent 假想对话流程

## 1. 典型输入链

1. 用户："我是一名金融分析师，最近负责过某基金的定量分析报告，想生成一份针对投研岗位的简历。"
2. Agent：识别意图为“投研简历篇幅+项目经验”，询问是否需要强调成果/工具栈。
3. 用户应答："强调成果，特别是那个基金项目的量化模型和结果。"
4. Agent：收集更多细节（时间、方法、团队规模），并确认是否需要自动润色语言。
5. Agent 生成草稿：按“项目经验”、“技能”、“荣誉”模块输出，并突出量化成果。
6. 用户反馈："再突出一下与风险管理相关的技能"，Agent 进入迭代。

## 2. 多场景思维

- **新手求职者**：意图可能是“生成简历 + 补充缺失信息”，Agent 主动询问学历/实习/奖项，提供模板引导。
- **转业人群**：重点在“转化经验”，Agent 识别主职业技能/可迁移能力，提示可加入跨行业项目描述。
- **高级管理岗**：关注战略/影响力，Agent 强调大局贡献、团队带领、KPIs。

## 3. Agent 模式设计

### 3.1 计划层（Planner）
- 问题分类：意图识别（岗位、侧重点、文风），分类后调不同模板/策略，例如“投研+量化” vs “销售+业绩驱动”。
- 对话管理：维护对话状态（已收集哪些信息、下一步还缺什么），并在多轮中回溯上下文。

### 3.2 执行层（Executor）
- 内容生成：调用 LLM 生成各模块段落，可通过结构化 Prompt（模块、关键词、语气、字数）来控制。
- 检验与纠错：输出后-run 格式校验（如是否包含 "成果" 和 "数据"），必要时再重写。
- 反馈采纳：将用户反馈纳入下一轮 Prompt，并在需要时插入“修改说明”字段，确保透明。

### 3.3 工具层（Tooling）
- 数据存取：查询历史对话、上传简历档案；提供模板库供执行层选择。
- 语义检索：如果用户提供关键词，Agent 可调用 embedding + vector DB 查找相关表述。
- 语法/润色：可接入 grammar 工具或翻译 API 确保语言地道。

### 3.4 异常/安全模式
- 不完整信息：自动触发“信息补全”子任务（使用 form-style 提问）而不是盲目输出。
- 多意图冲突：提示用户优先顺序，并提供两个版本供其选择。
- 敏感内容/隐私：屏蔽高敏感数据（比如身份证号）并提示用户改写。

## 4. 结果交付与记录

- 每次交付都会写入 `note/conversation_log.md`，以便记录迭代轨迹。
- 可导出 Markdown/Word/PDF，Agent 会确认用户想要的格式。
- 在 `md/` 中同步更新一份“成功案例”文档（例如 `md/use_cases.md`），含输入、Prompt、结果概览。
